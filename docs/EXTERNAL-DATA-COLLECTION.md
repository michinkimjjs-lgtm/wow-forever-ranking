# 외부 데이터 수집 정책과 설계

> 단계: 정책 재검토와 기술 설계 (2026-10-31). **구현 전 문서입니다.** 이 문서로 실제 수집을 시작하지 않습니다.
>
> 관련 문서: [`DATA-SOURCE-POLICY.md`](./DATA-SOURCE-POLICY.md), [`STATIC-GAME-DATA.md`](./STATIC-GAME-DATA.md), [`DATA-COLLECTION-STRATEGY.md`](./DATA-COLLECTION-STRATEGY.md), [`HISTORY-PRESERVATION.md`](./HISTORY-PRESERVATION.md)
>
> 이 문서는 법률 자문이 아닙니다. 외부 약관은 원문을 직접 읽은 뒤에만 "허용"으로 판단합니다.

## 1. 바뀌는 원칙

| 이전 | 이후 |
|---|---|
| 외부 사이트 scraping은 일괄 금지 | **출처마다 허용 여부를 판단한다.** 아래 허용 조건(§2)을 모두 만족하고 출처 등록부(§4)에 기록·승인된 출처만 수집한다 |
| 제3자 랭킹·Armory·census 데이터는 금지 | 이용 조건이 재사용을 허용하거나 운영자 허가를 받은 경우에만 허용. Raider.IO Forever API는 계속 제외(경쟁 서비스 구축 금지) |
| 공개 페이지라는 이유로 권한을 가정하지 않음 | **유지.** 공개·robots.txt 허용만으로는 재사용 권한이 생기지 않는다 |

바뀌지 않는 것:

- 수집한 데이터도 같은 수집 파이프라인(원본 저장 → 검증 → 파서 → 정규화 → 식별 → 저장)과 역사 기록 규칙을 거칩니다.
- 출처만으로 `VERIFIED`가 되지 않습니다.
- 특정 외부 사이트를 사이트 전체의 핵심 데이터 원천으로 고정하지 않습니다. 그 출처가 막혀도 사이트가 동작해야 합니다.
- 이미지와 데이터는 따로 판단합니다(§3.3).

## 2. 수집 허용 범위

### 2.1 허용하는 출처 (등록·승인 후)

| 유형 | 조건 |
|---|---|
| 공식 API | 공식 문서와 개발자 약관을 확인. 호출 한도·보존 기간·표시 의무를 지킴 (`BLIZZARD-API-INTEGRATION-PLAN.md`) |
| 사용 권한이 확인된 외부 데이터 | 권리자가 우리 용도(저장·표시·재가공·상업 여부)를 허용했다는 근거가 있음 |
| 오픈 라이선스 데이터 | 라이선스 이름·버전·원문 URL이 있고, 우리 용도를 허용함(예: CC0, CC BY, ODbL — 조건 준수) |
| 이용약관상 수집·재사용이 허용된 공개 웹페이지 | 약관 원문이 자동 수집과 재사용을 **명시적으로** 허용하고, robots.txt가 해당 경로를 막지 않음 |
| 운영자 허가를 받은 웹사이트 | 서면(이메일 등) 허가를 받아 보관. 허가 범위(항목·빈도·표시)를 등록부에 기록 |
| 사용자 제공·직접 제출 데이터 | 본인 캐릭터, 동의 화면 필수 (`SUBMISSION-SYSTEM.md`) |

### 2.2 허용하지 않는 수집 (출처와 무관하게 금지)

- 인증·로그인·유료 접근 제한 우회
- CAPTCHA·봇 차단 우회
- IP 변경·프록시 순환으로 차단 회피
- 비공개 내부 API의 무단 호출(공개 문서가 없는 사이트 내부 엔드포인트 포함)
- 개인정보·비공개 데이터 수집(계정 정보, 숨긴 정보, 다른 플레이어를 대상으로 한 `/who`·inspect 수집)
- 서버에 과도한 부하를 주는 수집(등록부의 요청 빈도를 넘는 수집, 동시 요청 남발)
- 저작권이나 데이터베이스 권리를 침해하는 대량 복제(사이트 전체 또는 대부분을 옮기는 수집)
- 출처와 사용 조건을 확인할 수 없는 이미지 파일의 저장·재배포
- 등록부에 없거나 승인되지 않은 출처의 수집

### 2.3 판단이 불확실할 때

허용 조건 중 하나라도 "확인 필요"면 **수집하지 않습니다.** 예외 없이 등록부 상태를 `PENDING`으로 둡니다.

## 3. 출처 등록부 (수집 전 반드시 기록)

### 3.1 기록 항목

출처 하나마다 아래를 모두 채워야 `APPROVED`가 될 수 있습니다.

| 항목 | 설명 |
|---|---|
| 출처 사이트 | 이름과 기본 주소 |
| 원본 URL | 수집할 페이지·API 주소(패턴) |
| 수집 대상 데이터 항목 | 예: 캐릭터 이름·레벨·직업, 아이템 이름·레벨. **이미지는 별도 행으로** |
| 이용약관 확인 결과 | 약관 URL, 확인 날짜, 수집·재사용 관련 조항 요약, 확인한 사람 |
| robots.txt 확인 결과 | 확인 날짜, 대상 경로 허용 여부, crawl-delay |
| 저작권자와 라이선스 | 권리자(사이트 운영자 / 게임사 / 사용자), 라이선스 이름·URL |
| 상업적 이용 가능 여부 | 가능 / 불가 / 확인 필요. 우리 사이트 운영 형태(§6.2)와 함께 판단 |
| 출처 표시 조건 | 표시 문구, 표시 위치(화면·푸터·API 응답) |
| 수집 허용 범위 | 항목·경로·최대 건수 |
| 요청 빈도와 갱신 주기 | 초당·시간당 최대 요청, 갱신 간격 |
| 데이터 보존·삭제 조건 | 최대 보존 기간, 다시 받기 주기, 삭제 요청 처리 |
| 운영자 허가 | 허가 여부·날짜·범위·보관 위치 (해당 시) |
| 상태 | `PENDING` / `APPROVED` / `SUSPENDED` / `REJECTED`, 결정 날짜와 결정한 사람 |

### 3.2 보관 형식 (구현 단계)

- 등록부는 코드 설정(`config/external-sources/*.ts`)으로 관리하고 스키마로 검증합니다(정적 데이터셋 설정과 같은 방식).
  - `APPROVED`가 아닌 출처는 수집기가 실행을 거부합니다.
  - 근거 URL과 확인 날짜가 없으면 설정 검증에서 실패합니다.
- 운영자 허가 메일 등 증빙은 저장소 밖(운영 문서 보관소)에 두고, 등록부에는 보관 위치만 적습니다.

### 3.3 이미지는 데이터와 따로 판단

- 사실 정보(캐릭터 레벨 등)를 쓸 수 있어도, 같은 사이트의 이미지(초상화·아이콘)는 별도 권리 판단이 필요합니다.
- 이미지는 다음을 모두 기록한 경우에만 로컬 파일로 저장합니다: 원본 URL, 권리자, 라이선스 또는 허가, 필요한 저작권 표시.
  - 외부 이미지 주소를 화면에서 직접 쓰지 않습니다(핫링크 금지).
- 게임사 소유 이미지는 그 게임사의 팬 사이트 조건을 원문으로 확인해야 합니다. 일반적으로 비상업 사용과 저작권 표시가 조건입니다(§6.2).
- 다른 사이트를 거쳐 받은 게임 이미지는, 그 사이트가 편집·가공했다면 그 사이트의 권리도 확인합니다.

## 5. 기술 설계

### 5.1 구성

```text
config/external-sources/          출처 등록부 (§3, 스키마 검증)
lib/external/
├─ source-registry.ts             등록부 읽기, APPROVED 확인, 중단 스위치
├─ fetcher.ts                     공통 HTTP: 속도 제한, robots.txt, 재시도, User-Agent
├─ adapters/<source>/             출처별 어댑터 (요청 만들기 + 응답 파싱 → CharacterObservation)
└─ run.ts                         작업 실행 (큐에서 호출)
providers/external/ExternalProvider.ts   기존 Provider 인터페이스로 연결
```

### 5.2 공통 동작

| 기능 | 설계 |
|---|---|
| 출처별 어댑터 | 어댑터는 "무엇을 요청하고 어떻게 해석하는지"만 안다. 요청 실행·속도 제한·기록은 공통 계층이 한다. 파서는 출처 버전(페이지 구조 버전)별로 분리 |
| 요청 속도 제한 | 등록부의 초당·시간당 한도와 robots.txt crawl-delay 중 **더 엄격한 값**. 출처별 토큰 버킷, 동시 요청 1개 기본 |
| robots.txt | 실행마다(캐시 24시간) 확인. 대상 경로가 막히면 실행 중단 |
| 식별 | 고정 User-Agent에 사이트 이름과 연락처. IP 변경·프록시 순환 없음 |
| 오류·재시도 | 5xx·네트워크 오류만 지수 백오프로 최대 3회. 429는 `Retry-After`를 따르고 그 회차 중단. 401·403·CAPTCHA 감지는 **재시도 없이 출처를 `SUSPENDED`로 바꾸고 운영자에게 알림** |
| 원본 보존 | 응답 원문(또는 해당 부분), 원본 URL, 수집 시각, 응답 상태, 어댑터·파서 버전을 `ingestion_records`에 저장. 재처리 가능 |
| 출처·신뢰도 | 새 `dataSource` 값(예: `external`)과 출처 ID를 저장. 검증 상태는 기본 `UNVERIFIED`. 등록부가 근거를 갖춘 경우에만 더 높은 상태를 정책으로 정함. 출처만으로 `VERIFIED` 아님 |
| 변경 이력 | 같은 대상의 이전 수집과 비교해 바뀐 항목만 기록(스냅샷 저장 규칙과 같음). 레벨은 근거(`level_milestone_evidence`)로 추가 |
| 출처별 중단 | 등록부 상태 `SUSPENDED` 또는 환경변수 차단 목록이면 즉시 중단. 진행 중인 작업도 다음 요청 전에 확인. 중단해도 이미 저장한 역사 기록은 지우지 않고 표시만 조정 |
| 보존·삭제 | 출처 조건의 최대 보존 기간을 넘으면 다시 받거나 표시에서 제외(Blizzard 30일 정책과 같은 구조, `lib/collection/retention.ts` 재사용) |

### 5.3 기존 검증과의 연결

- 어댑터 출력은 기존 `CharacterObservation` 형식이고, `ingestObservation`을 그대로 거칩니다(식별, 레벨 감소 충돌, 주장 판정, 근거 추가).
- 저장 행의 `dataEnvironment`는 서버 설정이 부여합니다. 외부 응답의 값을 믿지 않습니다.
- 외부 값이 다른 출처와 충돌하면 기존 우선순위(`VERIFIED → … → UNVERIFIED`)와 근거 판정 규칙을 따릅니다.
- 화면에는 출처 표시 조건대로 출처를 표시합니다. 표시할 수 없으면 그 데이터를 쓰지 않습니다.

### 5.4 필요한 스키마 변경 (구현 단계, migration)

- `data_source` enum에 외부 출처 값 추가와 관련 CHECK 조정
- `external_sources`(등록부 사본·상태 이력), `external_fetch_log`(요청 기록: 출처, URL, 시각, 상태, 소요 시간) — 새 테이블로 추가, 기존 테이블을 다시 설계하지 않음

## 6. 위험

### 6.1 법적 위험

| 위험 | 내용 | 대응 |
|---|---|---|
| 약관 위반 | 자동 수집·경쟁 서비스 구축을 금지하는 약관 | 원문 확인 전 수집 안 함, 등록부 승인 절차 |

### 6.2 운영 형태 결정 필요

게임사 팬 사이트 조건은 일반적으로 비상업 사용을 전제로 합니다. Forever Rank의 광고·후원·유료 기능 여부가 문서로 정해져 있지 않습니다. 게임사 콘텐츠를 쓰기 전에 운영 형태를 정하고, 수익화하면 권리를 다시 확인합니다.

### 6.3 기술적 위험

- 페이지 구조 변경으로 파서가 잘못 해석 → 파서 버전 분리, 필수 항목 누락 시 해당 건 거부, 이상치 감지(레벨 감소는 식별 충돌)
- 출처 데이터의 정확성을 우리가 보증할 수 없음 → 낮은 검증 상태, 출처 표시
- 출처 의존 → 핵심 원천으로 고정하지 않음, 중단 스위치
- 차단·속도 제한 → 우회하지 않고 중단

## 7. 실제 수집을 구현하는 순서

1. **정책 확정:** 이 문서와 정책 문구 변경을 검토·승인하고, 운영 형태(§6.2)를 결정합니다.
2. **출처 조사:** 작업 환경에서 대상 도메인 접속을 허용하고, 약관·robots.txt 원문을 확인해 등록부 초안을 씁니다. 필요하면 운영자에게 서면 허가를 요청합니다.
3. **등록부 구현:** `config/external-sources` 스키마와 검증, `APPROVED`만 실행되는 확인 로직, 테스트.
4. **공통 수집 계층:** fetcher(속도 제한, robots.txt, 재시도, 중단), 요청 기록 테이블 migration. 실제 외부 호출 없이 가짜 서버로 테스트.
5. **첫 어댑터:** 승인된 출처 하나만, 항목 최소로. 파서 테스트는 저장한 샘플 응답으로(재배포 가능한 범위).
6. **파이프라인 연결:** `ExternalProvider` → `ingestObservation`. `dataSource` migration, 검증 상태 정책, 출처 표시 화면.
7. **mock·beta에서 검증** 후, 운영 영역 적용은 별도 승인.
8. **운영:** 수집 로그 모니터링, 정기 약관 재확인(등록부 확인 날짜 기준), 이미지 권리 기록 유지.
