# 개인정보·데이터 정책 (제출 데이터)

> 정책 버전: `privacy-2026-10-07`
> 동의 문구 버전: `consent-2026-10-07` (`config/submissions.ts`)
> 단계: Phase 3A
>
> 관련 문서:
> - [`DATA-SOURCE-POLICY.md`](./DATA-SOURCE-POLICY.md) §7~§11
> - [`SUBMISSION-SYSTEM.md`](./SUBMISSION-SYSTEM.md)
>
> 이 문서는 서비스 운영 원칙이며 법률 자문이 아닙니다. 정식 공개 전에 관련 법령(개인정보 보호법 등) 검토가 필요합니다(확인 필요).

## 1. 처리하는 데이터

Character Export v1에 담긴 **본인 캐릭터의 게임 데이터**만 처리합니다.

| 데이터 | 용도 | 공개 여부 |
|---|---|---|
| 캐릭터 이름, 성 | 캐릭터 표시, 식별 | 공개 (랭킹·Armory) |
| 레벨, 직업, 종족, 진영, 길드 이름 | 랭킹, Armory | 공개 |
| 장착 장비 (아이템 번호, 아이템 레벨, 품질, 링크 이름) | 장비 랭킹, Armory | 공개 |
| 레벨 상승 시각, 데이터 생성 시각, 클라이언트 빌드 | 최초 달성 기록, 최신성 | 공개 (시각) |
| 게임 캐릭터 고유 식별값(GUID) | 같은 캐릭터 찾기, 중복·충돌 확인 | **비공개** (화면·공개 API에 표시 안 함) |
| 동의 기록 (동의 문구 버전, 정책 버전, 동의 시각) | 동의 증빙 | 비공개 |
| 제출 시각, 검토 상태, 검토 메모 | 관리자 검토 | 비공개 |

## 2. 수집하지 않는 데이터

- Battle.net 비밀번호, Battle.net 인증정보(인증기 코드 등), 계정 비밀번호
- Battle.net 계정 이름, BattleTag, 이메일
- 결제 정보, 실명, 연락처, 주소
- 다른 플레이어의 정보, 채팅, 위치
- 파일이 저장된 폴더 경로 (계정 폴더 이름이 들어 있음). 브라우저는 파일 내용만 보냅니다.
- **IP 주소는 저장하지 않습니다.**
  - 과도한 요청을 막기 위해 IP와 User-Agent로 하루 동안만 같은 값이 되는 일시 식별값(HMAC)을 계산합니다.
  - 이 값은 메모리에서만 씁니다. DB·로그에 남기지 않습니다.
  - 호스팅 플랫폼의 접근 로그 보관 정책은 배포 환경에 따라 다릅니다(확인 필요).

## 3. 실수로 들어간 개인정보 막기

- 제출 전에 브라우저와 서버가 모두 export의 문자열과 키를 검사합니다(`lib/submissions/sensitive.ts`).
- 다음으로 보이는 값이 있으면 제출을 받지 않습니다.
  - 이메일, BattleTag 형식(`이름#숫자`)
  - 비밀번호·인증 관련 단어
  - 카드번호, 주민등록번호, 휴대전화 번호 형식
  - `password`, `email`, `token`, `account` 같은 키
- 이 검사는 실수를 줄이기 위한 장치입니다. 모든 개인정보를 찾아낸다고 보장하지 않습니다.
- 동의 2번 항목에서 "개인정보가 포함된 파일을 제출하지 않았음"을 사용자가 직접 확인합니다.
- 서버는 스키마에 없는 필드를 버리고, 검증한 값만 보관합니다.

## 4. 동의

제출 버튼 전에 두 항목에 모두 동의해야 합니다.

1. 내가 제출한 캐릭터 데이터가 랭킹과 서비스 품질 개선을 위해 사용되는 것에 동의합니다.
2. 개인정보가 포함된 파일을 제출하지 않았음을 확인합니다.

저장하는 동의 기록:

- `consentVersion`, `policyVersion`
- `consentedAt`: 서버 시각. 클라이언트 시각을 믿지 않습니다.

규칙:

- 공개 제출은 동의 기록 없이 저장할 수 없습니다. DB CHECK로 강제합니다.
- 문구가 바뀌어 버전이 다르면 서버가 거부하고, 다시 동의하도록 안내합니다.

## 5. 사용 목적

- 커뮤니티 랭킹(레벨 / 장비 / 최고 아이템), 캐릭터 Armory, 길드 정보
- 중복·충돌 확인, 데이터 품질 개선, 게임 값 매핑 확인
- 제3자에게 판매하거나 대량 제공하지 않습니다([`DATA-SOURCE-POLICY.md`](./DATA-SOURCE-POLICY.md) §6).

## 6. 공개 범위와 검증 상태

- 승인된 제출만 랭킹과 Armory에 표시됩니다.
- 출처는 "커뮤니티 제출", 검증 상태는 "커뮤니티 제출"로 표시합니다.
- 제출이나 관리자 승인만으로 "검증됨"이 되지 않습니다.

## 7. 보존

| 데이터 | 보존 |
|---|---|
| 제출 기록 (`character_submissions`) | 검토·재처리를 위해 보관. 거부한 제출도 감사 목적으로 보관. 보관 기간은 정식 공개 전 결정 (확인 필요) |
| 승인되어 반영된 캐릭터 데이터 | 랭킹 데이터 정책을 따름 (삭제하지 않고 7일 기준으로 랭킹 제외) |
| 요청 제한용 일시 식별값 | 메모리에서만. 서버 재시작 또는 시간 창이 지나면 사라짐 |

## 8. 삭제 요청

- 제출이 끝나면 제출 번호가 표시됩니다. 삭제 요청에 필요합니다.
- 삭제 요청 창구(연락 방법)는 **정식 공개 전에 `/submit` 화면에 안내합니다**. 현재는 준비 중입니다.
- 소유 확인 방법: 같은 캐릭터로 새 export를 만들어 제출 번호와 함께 보내는 방식을 검토 중입니다(확인 필요).
- 처리 내용:
  - 화면·API에서 숨김
  - 제출 원본 삭제 또는 익명화
  - 순위 재계산
- 숨김·삭제 처리 기능은 다음 단계에서 구현합니다. 기존 테이블을 다시 설계하지 않고 별도 테이블로 추가합니다.

## 9. 변경

정책이나 동의 문구를 바꾸면 버전을 올립니다. 이전 버전으로 받은 동의 기록은 그대로 보관합니다.
